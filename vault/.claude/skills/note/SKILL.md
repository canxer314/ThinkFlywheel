# /note Command

将对话中的研究内容整理为知识卡片，存入 Obsidian。**双提议机制**: AI 提议 wikilinks（链接已有卡片）+ 原子卡片（创建新卡片），用户确认后写入。

## 核心理念：地图 + 石头

每次 `/note` 产出两层内容：

1. **研究摘要（地图）** — 一张完整的叙事性卡片，保留讨论的脉络、推理链条和结论。读这张就能还原整个研究过程。
2. **原子卡片（石头）** — 从摘要中提炼的独立知识点，每张可脱离上下文复用，最终进入 FSRS-6 间隔重复。

**地图让石头有意义，石头让地图可链接。**

## 定位

`/note` 是 vault 中知识类卡片的**唯一写入通道**（SCHEMA.md §3）。

| 上游 | 下游 |
|------|------|
| `/ingest` 处理来源后的结构化内容 | `/review` 原子卡片进入 FSRS-6 复习 |
| `/retro` 任务复盘后的教训提取 | `/query` 卡片被检索时找到 |
| 纯对话中产生的洞察和认知 | `/briefing` 复习卡片交叉引用到活跃任务 |

## Behavior

### Step 1: 确定范围

根据 `scope` 参数确定要扫描的对话范围：
- `all`: 整个对话（默认）
- `last`: 最近一轮讨论
- `select`: 让用户指出要处理的具体内容

### Step 2: 扫描和去重

扫描对话内容，识别值得沉淀的知识点：

**值得沉淀的内容类型**：
- 新学到的概念、模型、框架
- 从实践中总结的教训和模式
- 纠正的误解或发现的反模式
- 跨来源的对比和综合判断
- 决策背后的理由和假设

**跳过的内容类型**：
- 已经在 vault 中有几乎相同卡片的内容（去重——告诉用户"这已有卡片 [[X]]，跳过"）
- 纯操作性的对话（"打开文件"、"运行命令"）
- 临时性的状态描述

### Step 3: 展示双提议（核心）

向用户展示双提议，**同时**展示摘要草稿和原子卡片草稿：

---

**📋 研究摘要草案**

```markdown
# [主题] — 研究摘要

> 日期: {{today}} | 来源: [对话起因]

## 研究背景
[为什么讨论这个]

## 核心发现
[关键结论和推理链]

## 待验证
[不确定的地方，标记为 draft]
```

---

**🔗 提议 1: Wikilinks（链接到已有卡片）**

以下对话中提到的概念已有对应卡片，AI 建议在摘要中添加以下 wikilinks：

| 对话中的概念 | 已有卡片 | 建议 |
|-------------|---------|------|
| [概念 A] | [[Card A]] | 添加到摘要 |
| [概念 B] | [[Card B]] | 添加到摘要 |

---

**🆕 提议 2: 原子卡片（新创建）**

以下知识点值得独立成卡，未来可进入 FSRS-6 复习：

| # | 标题 | 一句话描述 | 类型 |
|---|------|-----------|------|
| 1 | [建议标题] | [一句话说清楚这个概念] | atomic |
| 2 | [建议标题] | [一句话说清楚这个教训] | insight |

用户可选择: 全部接受 / 勾选部分 (输入 "1,3" 或 "1 3") / 全部拒绝 (输入 "no" 或 "skip")

---

### Step 4: 执行用户选择

用户确认后：

1. 如果用户修改了卡片标题或内容，使用修改后的版本
2. 创建被接受的卡片到对应目录（`Cards/atomics/` 或 `Cards/insights/` 等）
3. 创建研究摘要到 `Cards/reading/`（如果内容来自 ingest）或 `Cards/concepts/`（如果是新概念）
4. 给所有新卡片添加 frontmatter：
   - `source` 回链到来源卡片或任务
   - `related_tasks` 如果调用时有活跃任务上下文，自动添加
5. 如果用户拒绝某张卡片，不写入（但记录到 log 中供后续参考）

### Step 5: 更新索引（AI 自主）

- 更新 `index.md` 的对应分类
- 更新相关 domain 的 MOC
- 追加 `log.md`: `## [YYYY-MM-DD] note | X cards created, Y wikilinks added`
- 如果有原子卡片被创建，提醒用户: "新卡片将在下次 /review 时进入复习队列"

---

## 去重规则

在提议新卡片前，搜索 vault 中是否已有覆盖相同概念的卡片：

1. 搜索 `Cards/` 中标题或内容相似度高的卡片
2. 如果已有卡片覆盖了 80% 以上的内容: 不提议新建，建议补充已有卡片
3. 如果已有卡片但角度不同: 提议新建 + wikilink 互链

---

## 与 /retro 的关系

`/note` 和 `/retro` 都会触发知识提取，但入口不同：

| | /note | /retro |
|--|-------|--------|
| 触发场景 | 对话中产生了知识 | 任务完成后做复盘 |
| 主要来源 | 讨论、阅读、分析 | "问题与吐槽"中的实际经验 |
| 卡片类型偏好 | concept、atomic | insight、atomic |
| 是否归档任务 | 否 | 是 |
