# /project Command

创建和管理专案目标笔记 — 三层任务架构中的"鸟瞰地图"层。

## 核心理念

> 专案笔记是鸟瞰地图——只做目标定义、任务索引、进度评估、经验沉淀。不直接执行，所有行动通过下层 Task 推进。

## Behavior

### Step 1: 专案完成定义优先

第一个问题不是"要做什么",而是"做完了什么样"。

在收集动机、里程碑之前,先与用户确认专案完成定义:
- "这个专案干完了,你能交付什么?"
- "成功的标准是什么?如何衡量?"
- 必须是可验证的成果状态,不能是模糊意向

### Step 2: 查询历史上下文

自动搜索 vault,为新专案预填经验:

1. `Projects/archived/` — 同领域历史专案的"经验区"有什么教训?
2. `Flows/{domain}/` — 此专案会用到哪些永久型流程?预填到 related_flows
3. `Cards/insights/` — 匹配的教训卡片
4. `Decisions/` — 相关的历史决策

### Step 3: 创建专案笔记

在 `Projects/active/{Title}.md` 用 `Templates/project.md` 创建,AI 预填:

- **🎯 专案完成定义**: 用户确认的成果标准
- **💡 立项动机**: 用户描述 + AI 提炼"为什么现在做"
- **🗺️ 里程碑地图**: AI 建议 2-4 个里程碑,用户调整
- **📋 任务清单**: 留空,等待 `/task` 创建任务时自动填入
- **📎 关联流程**: Step 2 查到的 flows
- **📊 进度评估**: 初始 0%、on-track
- **🚧 专案级问题与决策**: 留空
- **💡 专案经验区**: 留空

### Step 4: 任务关联(双向链接)

当用户用 `/task` 创建任务且 project 字段指向此专案时:

- 任务 frontmatter `project:` [[此专案]]
- 专案"任务清单"自动追加 🔲 `[[任务]]` — {完成定义摘要}

### Step 5: 进度评估机制

**触发时机**(三选一):
1. 关联任务状态变化(`/task` 更新时主动触发)
2. 用户主动询问"专案进度"
3. 每周定时(在 `/briefing` 中检查)

**评估逻辑**:
1. 扫描所有关联任务的 status
2. 计算 完成度 = done任务数 / 总任务数
3. 检查里程碑日期是否逾期
4. 计算态势:
   - 🟢 on-track: 按计划推进,无逾期里程碑
   - ⚠️ at-risk: 有任务 waiting 超过 7 天,或里程碑可能逾期
   - 🔴 stalled: 14 天以上无任务状态变更
5. 更新"进度评估"节,写明评估理由(不只是状态)

### Step 6: 子任务完成时的"回归"动作

每当一个关联任务被 `/retro` 归档时,自动:

1. 任务清单对应行从 🔲 改为 ✅,追加完成日期
2. 重新触发 Step 5 进度评估
3. 检查任务复盘是否有"专案级洞察"标记 → 追加到专案"💡 专案经验区"
4. 检查任务"问题与吐槽" → 评估是否升级到专案级 → 追加到"🚧 专案级问题与决策"
5. 基于最新认知,提示用户:"专案完成定义需要调整吗?剩余任务是否还有效?"

### Step 7: 专案完成

当用户说"专案完成"或所有里程碑勾选完毕:

1. AI 触发专案级 `/retro`:
   - 汇总所有子任务的复盘
   - 提取专案级洞察 → 原子卡片(走 `/note` 双提议)
   - 检查是否产生新的永久型流程 → 提议创建 type: flow 笔记
2. 标记 `status: completed`
3. 生成专案终期复盘,写入 `Reviews/retro/`
4. 移动到 `Projects/archived/`
5. 更新 `index.md`

## 月度脉搏(AI 自主)

每月初或用户首次打开 `/briefing` 时:
1. 检查所有活跃专案的 `updated` 是否跨月
2. 对每个跨月专案,主动提示:"专案 X 上月完成 n 个任务,有 m 条新问题,是否做月度复盘?"
3. 同意 → 触发 Step 7 的"月度迷你复盘"模式(不归档,只沉淀经验)

---

## 与三层架构的协作

> Project ↔ Flow (related_flows) ↔ Task (project 字段)。Task 完成后 /retro 三向回流：原子卡 + Flow 经验 + Project 经验区。

## 反模式警告

- 不要在专案笔记里写"下一步行动" — 那是任务笔记的事
- 不要让专案笔记承载执行细节 — 它是地图不是工地
- 不要把 Risk Log 做成 PMO 风险登记册 — 用"专案级问题与决策"承载真实摩擦

## 失败处理

| 场景 | 处理 |
|------|------|
| **Templates/project.md 不存在** | 手动构建 frontmatter + 8 节结构（完成定义、立项动机、里程碑地图、任务清单、关联流程、进度评估、问题与决策、经验区）；提醒用户检查模板 |
| **同名专案已存在** | 询问用户：更新已有专案 / 换名创建 / 取消 |
| **Projects/active/ 目录不存在** | 创建目录；失败则告知"vault 目录结构异常，建议运行 /health" |
| **历史查询（archived/Flows/Insights/Decisions）全部为空** | 告知"vault 中暂无相关历史经验"，创建空白专案，后续执行中积累 |
| **进度评估时关联任务全部 waiting**（无进行中/完成） | 标记为 stalled，提示用户"所有关联任务均阻塞，建议逐项检查阻塞原因" |
| **里程碑日期格式错误或缺失** | 不阻塞创建，标注"⚠️ 待补充日期"，提醒用户后续补全 |
