# /briefing Command

生成每日上下文简报。这是 ThinkFlywheel 的**核心融合点**——任务层(L3)、知识层(L2)、记忆层(L1)在此交汇为一张可操作的早晨视图。

## 核心理念

不是让你从空白开始每一天。而是把系统里所有与你相关的上下文——你在做什么、你知道什么、你该复习什么、哪些项目需要关注——全部汇总到一个地方。

## Behavior

### Step 1: 扫描活跃任务

读取 `Tasks/active/` 下所有任务笔记，提取：

- 任务标题 + wikilink
- `status`: 特别标记 `waiting` 状态的任务（阻塞中）
- `domain`
- 最新"下一步行动"中未勾选的条目
- `updated` 日期：标记超过 7 天未更新的任务 ⚠️，超过 14 天的 🔴
- `due` 日期：标记 3 天内到期的 🔴，7 天内 ⚠️

按优先级排序：
1. 即将到期的任务
2. doing 状态 > waiting 状态 > todo 状态
3. 最近更新过的在前

### Step 2: 检测到期复习卡片

调用 FSRS-6 引擎获取今日到期卡片：

```bash
python .obsidian/scripts/fsrs_engine.py .obsidian/review_state.json due --limit 20
```

对每张到期卡片：
- 读取卡片内容，提取主题关键词
- 按 `domain` 分组

### Step 3: 交叉引用（核心融合）

对每张到期复习卡片，搜索 vault 中是否存在关联：

1. 卡片 frontmatter 中是否有 `related_tasks`？如果有，直接建立链接
2. 卡片的 `domain` 与哪些活跃任务的 `domain` 匹配？
3. 卡片标题/内容中的关键词是否出现在活跃任务的"原始材料堆"中？

结果：每张复习卡片标记为：
- **"关联活跃任务"** — 标注重点复习 + 标注关联任务名
- **"无关联任务"** — 你的知识库中有这块知识，但当前没有在用的任务

### Step 4: 检查项目健康

读取 `Projects/active/` 下所有项目，提取进度脉搏：

- on-track: 绿色 🟢
- at-risk (有阻塞任务或里程碑逾期): 黄色 ⚠️
- stalled (14 天以上无任务活动): 红色 🔴

### Step 5: 历史预警

扫描 `Tasks/archived/` 中与当前活跃任务 domain 相同的历史任务，检查：

- 历史任务的"问题与吐槽"中是否有重复出现的模式？
- 当前活跃任务是否有类似的特征（相似的最终目标、相似的材料堆）？
- 如果有，提取为"历史警告"

### Step 6: 生成简报

按以下结构输出 `Daily/YYYY-MM-DD.md`（如果今天已有则直接展示）：

```markdown
# {{date}} 每日简报

## 🔥 今日焦点（1-3 个最重要的事）
{从活跃任务中选出最紧急/重要的 1-3 项}

## 📋 活跃任务
| 优先级 | 任务 | 状态 | 下一步 | 更新 |
|--------|------|------|--------|------|
| HIGH | [[Task A]] | doing | review draft | 今天 |
| MEDIUM | [[Task B]] | waiting | 等反馈 | 3天前 ⚠️ |

## 🧠 今日复习（FSRS 到期卡片）
| 卡片 | 关联任务 | 
|------|---------|
| [[SBI 反馈框架]] | → [[Task B]] 💡 |
| [[数据可视化的3原则]] | (无关联任务) |

## 📊 项目健康
| 项目 | 状态 | 活跃任务数 | 本周完成 |
|------|------|-----------|---------|
| [[Project X]] | 🟢 on-track | 3/5 | 2 |
| [[Project Y]] | 🔴 stalled | 0 | 0 |

## ⚠️ 历史预警
{从历史类似任务的"问题与吐槽"中发现的可能模式}

## 📝 今日概览
- 活跃任务: {count}
- 到期复习: {count}
- 阻塞任务: {count}
- 即将到期: {count}
```

### Step 7: 更新索引

- 更新 `log.md`: `## [YYYY-MM-DD] briefing | daily context generated`
- Daily 文件保留最近 14 天，AI 检查并提示清理旧的

---

## 注意事项

- 简报是**临时性文件**，每天重新生成，不累积
- 交叉引用是简报的核心价值——不是简单的列表，而是**有上下文的关联**
- 如果 vault 中还没有内容（Phase 1 初期），简报只显示活跃任务部分——这很正常
- "历史预警"在 Phase 1-2 数据不足时可能为空——随着使用积累会逐渐有价值
- 简报不应要求用户做任何输入，纯读取和展示
