# /flow Command

创建永久型任务笔记 — Esor 三层架构的最上层"能力库"。

## 核心理念

> 反复做的事,值得有自己的家。

永久型任务笔记不是任务,是任务的元任务 — 它提炼出"这类事情应该怎么做"的方法论。每次执行同类任务,都从这里开始;每次完成同类任务,经验都回流到这里。

## 何时创建 Flow?

满足以下任一条件:
- 同一类任务已经做过 3 次以上
- 用户明确说"以后这种事都按这个流程来"
- `/retro` 时 AI 识别出"这是可复用流程"
- 用户首次建立一个明显会反复执行的事项(如"每周周报")

## 何时不创建 Flow?

- 一次性任务 → 用 `/task`
- 多任务集合有终点 → 用 `/project`
- 单纯知识/方法论 → 用 `/note` 创建概念卡

## Behavior

### Step 1: 命名规范

强制名词性命名,后缀建议:
- "流程"(如"周报撰写流程")
- "SOP"(如"客户谈判 SOP")
- "检查清单"(如"新成员入职检查清单")
- "手册"(如"问题排查手册")

### Step 2: 查询历史任务

如果 vault 中已有同类历史任务:

1. 扫描 `Tasks/archived/` 中标题相似的任务
2. 汇总它们的"行动步骤"找共性 → 作为"📋 标准步骤"初稿
3. 汇总它们的"问题与吐槽"和"复盘与衍生" → 作为"⚠️ 易错点与陷阱"初稿
4. 提取常用资源链接 → 作为"🧰 资源与模板"

### Step 3: 创建流程笔记

在 `Flows/{domain}/{Title}.md` 用 `Templates/flow.md` 创建,AI 预填:

- **📌 适用场景**: 触发条件、何时启用
- **🎯 流程目标**: 这个流程要解决的核心问题
- **📋 标准步骤**: 从历史任务提炼或用户给定
- **⚠️ 易错点与陷阱**: 从历史沉淀
- **🧰 资源与模板**: 常用工具和文档
- **📈 迭代日志**: 初始版本 v1

### Step 4: 反向回填历史任务

创建后,扫描历史相似任务,在它们的 frontmatter `flow` 字段填入此流程链接(用户确认)。这样未来 `/briefing` 可以看到"此流程历次执行情况"。

---

## 流程的迭代机制

### 经验回流(由 /retro 触发)

每当一个使用此流程的任务完成时,`/retro` 会:

1. 询问用户:"本次执行有什么对流程本身的改进建议?"
2. 如有改进:
   - 更新流程的"📋 标准步骤"或"⚠️ 易错点"
   - 递增 `version` 字段
   - 追加"📈 迭代日志": `[YYYY-MM-DD] v{n+1} | 来自 [[任务]] | 改动: xxx`
3. 如本次踩到的坑是新的 → 追加到"⚠️ 易错点"

---

## 流程的"激活"机制

在 `/briefing` 中,根据 `trigger` 字段主动唤起:

- `weekly-fri` → 每周五早晨提示"今天该执行 [[周报撰写流程]] 了,是否创建本周任务?"
- `monthly-1` → 每月 1 日提示
- `on-demand` → 不主动提示,用户启用 `/task --flow xxx` 时使用
- `event:xxx` → 特定事件触发(预留扩展)

用户同意激活 → 自动调用 `/task`,且 `flow` 字段预填、行动步骤继承自流程。

---

## 状态管理

- `active`: 现行流程,持续使用和迭代
- `deprecated`: 已弃用,但保留供历史参考(不删除)

**永久型笔记没有 done 状态** — 这是它和任务的本质区别。

---

## 失败处理

| 场景 | 处理 |
|------|------|
| **Tasks/archived/ 中无相似任务** | 告知用户"未找到历史类似任务，将创建空白流程模板，后续执行中积累经验"；标准步骤由用户口述或 AI 提议通用步骤 |
| **历史任务的"行动步骤"为空** | 跳过共性提取，标准步骤留空待用户填写 |
| **Templates/flow.md 不存在** | 手动构建 frontmatter + 章节结构（适用场景、流程目标、标准步骤、易错点、迭代日志）；完成后提醒用户检查模板文件 |
| **同名 flow 已存在** | 询问用户：更新已有流程 / 换名创建 / 取消 |
| **trigger 字段值不在已支持列表中**（非 weekly-fri/weekly-mon/monthly-1/on-demand/event:xxx） | 仍接受并写入 frontmatter，但告知用户"该 trigger 值目前不会被 /briefing 自动识别，需手动激活" |

---

## 反模式警告

- 不要为每件事都建流程 — 流程的价值在于"反复"
- 不要把流程当任务执行 — 它是模板,每次执行都通过 `/task` 实例化
- 不要让流程僵化 — `version` 字段就是为了提醒"流程应该进化"
