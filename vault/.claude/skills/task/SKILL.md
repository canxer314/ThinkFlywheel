# /task Command

创建暂时性任务笔记 — ThinkFlywheel 飞轮的行动入口。

## 核心理念

任务笔记是"行动指挥中心",不是待办条目。打开它,所需一切都在手边。

## 准入校验(Step 0,创建前必做)

接收到任务描述后,先用 Esor 的四个过滤器自检:

1. **行动承诺**: 用户是否真的要为此投入时间?(不是兴趣/愿望)
2. **具体成果**: 完成时能交付可验证的产出?
3. **多步骤性**: 需要2步以上完成?(单步动作不值得建任务)
4. **需整合信息**: 需要汇集多源信息?

- 如果 2 分钟内可完成的单步动作 → 建议用户直接做掉,不建任务。
- 如果是模糊意向("研究一下"、"了解一下") → 反问用户具体成果是什么。
- 如果是纯知识/收藏 → 建议用 `/note` 而非 `/task`。

## Behavior

### Step 1: A-F-O-T 命名重写

按 **动词 + 对谁 + 成果 + 时地** 重写用户的原始描述:

- 原始: "客户报告" → 重写: "撰写给A客户的Q2销售分析报告(含3图表+1结论页),周三午前邮件发出"

如果用户输入缺失要素,在创建前向用户追问关键缺失项(最多 2 个问题):
- 缺动词 → "这件事你要做什么动作?撰写?整理?汇报?"
- 缺成果 → "完成时应该交付什么具体产出?"
- 缺时地 → "什么时候之前需要完成?"

不强制四要素全填,但完成定义(成果)是必须的。

### Step 2: 查询 Vault 上下文

在创建笔记之前,自动扫描:

1. `Flows/{domain}/` — 是否有匹配的永久型任务流程?如有,作为 flow 字段候选,并提取"标准步骤"作为行动步骤初稿
2. `Projects/active/` — 任务标题或描述是否提及活跃专案?如有,作为 project 字段候选
3. `Tasks/archived/` — 历史相似任务的"复盘与衍生"区有什么经验?有什么"问题与吐槽"作为警告?
4. `Cards/insights/` — 是否有相关教训卡片?
5. `Decisions/` — 是否有影响此任务的决策?

### Step 3: 创建任务笔记

在 `Tasks/active/{A-F-O-T Title}.md` 用 `Templates/task.md` 创建,AI 预填:

- **🎯 完成定义**: 从重写后的标题中提取"成果"部分,扩展为一句完整描述
- **⚡ 下一步行动**: 用"行动回推法"找出无前置依赖的第一步物理动作
- **✅ 行动步骤**: 若 flow 关联,继承流程的"标准步骤";否则提议 3-5 步拆解
- **📎 资料与素材**: 列出 Step 2 查询到的相关链接,带 [[wikilinks]]
- **📝 进度日志**: 留空,等待执行时填写
- **💬 问题与吐槽**: 留空
- **💡 复盘与衍生**: 留空,/retro 时填写

### Step 4: 自主索引更新(无需确认)

1. 更新 `index.md` 的 "Active Tasks" 节
2. 追加 `log.md`: `## [YYYY-MM-DD HH:mm] create task | {Title}`
3. 如 project 关联,在专案笔记"任务清单"节追加 🔲 `[[任务]]` — {完成定义摘要}
4. 如 flow 关联,在流程笔记"历史执行记录"节追加链接
5. 更新对应领域 MOC

### Step 5: 输出确认

向用户展示:
- 重写后的 A-F-O-T 标题(请确认或修改)
- 完成定义(请确认)
- Next Action
- 行动步骤草稿
- Vault 查到的相关材料数量(及关键警告)

**重要**: 任务笔记直接写入,不走双提议。质量门控在 `/retro` 时。

## 更新已有任务

当用户说"task update"/"任务进度"/"更新任务"时:

1. 读取已有任务
2. 追加进度日志(带时间戳),而非覆盖
3. 若用户描述了新摩擦 → 追加到"问题与吐槽"
4. 若用户完成了某步 → 勾选对应 ✅ 行动步骤,并重新生成 Next Action(指向下一个未完成步骤)
5. 更新 frontmatter `updated`
6. 如关联了专案,触发专案"进度评估"重新计算

## 状态流转

```
todo → doing → waiting → done → archived
  ↑                ↓        ↓
  └──── 恢复 ──────┘    /retro 触发归档
```

- `todo`: 已创建,尚未开始
- `doing`: 正在执行
- `waiting`: 阻塞中(必须在"问题与吐槽"记录阻塞原因和等待对象)
- `done`: 已完成,等待 /retro 复盘
- `archived`: 已复盘归档

## 失败处理

| 场景 | 处理 |
|------|------|
| **Vault 中无匹配 Flow** | 跳过 flow 关联，不强制；告知用户"未找到匹配流程，后续如有需要可手动关联" |
| **Vault 中无匹配 Project** | 跳过 project 关联，不强制；告知用户"如属于某个专案，可后续手动设置 project 字段" |
| **Templates/task.md 不存在** | 手动构建 frontmatter + 7 节结构（完成定义、下一步行动、行动步骤、资料与素材、进度日志、问题与吐槽、复盘与衍生）；完成后提醒用户检查模板 |
| **同名任务已存在** | 询问用户：覆盖 / 追加版本号后缀 / 换名 / 取消 |
| **用户输入的 A-F-O-T 要素缺失过多** | 不创建空壳任务，逐要素追问（最多 2 个问题），完成定义必须确认后才创建 |
| **Files 写入目录不存在**（Tasks/active/ 缺失） | 先创建目录再写入；如创建失败，告知用户"vault 目录结构异常，建议运行 /health 检查" |

## 🚫 不要做什么（反模式）

| # | 反模式 | 为什么不要做 | 正确做法 |
|---|--------|-------------|---------|
| 1 | **对单步动作（<2分钟）建任务** | 任务管理成本超过执行成本 | Step 0 四过滤器拦截，建议直接做掉 |
| 2 | **任务描述模糊仍直接创建** | 模糊的任务无法执行，最终僵死 | 反问用户完成定义，确认后创建 |
| 3 | **把纯知识/收藏建为任务** | 任务不是知识库——没有行动=没有产出 | 引导用户用 /note 而非 /task |
| 4 | **跳过 vault 上下文查询** | 任务孤立创建，错过已有的流程/专案/经验 | Step 2 强制扫描 Flows/Projects/Insights/Decisions |
| 5 | **对 task 笔记做双提议确认** | 任务不是知识，不需要质量门控 | /task 直接写入，质量门控在 /retro 时执行 |
| 6 | **更新任务时覆盖原有进度日志** | 进度日志是时间线——覆盖=丢失历史 | 追加新条目（带时间戳），不覆盖已有内容 |

## 与三层任务架构的协作

> Task 引用 Flow（flow 字段）和 Project（project 字段）。完成后 /retro 三向回流：原子卡片 + Flow 经验 + Project 洞察。
