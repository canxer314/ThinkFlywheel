## 每日节奏：什么时候用哪个技能

```
早晨刚坐下      → /briefing    每天唯一必跑
开始做一件事    → /task        新任务、新想法、别人交代的事
开了一个会议    → /meeting     记录会议纪要、行动项、决议
建立标准流程    → /flow        固化 SOP/检查清单/流程模板
执行中遇到阻塞  → /task        更新状态、追加"问题与吐槽"
读了一篇文章    → /ingest      处理成阅读摘要+提取知识点
对话中学到东西  → /note        从对话中提取, 存为卡片
做完了一件事    → /retro       复盘+提取知识（关键桥接技能）
晚上空闲        → /review      5-10分钟复习到期卡片
需要找东西      → /query       搜索 vault
要做重要选择    → /decide      结构化记录+未来复查
周末/月末       → /health      全面体检

/briefing → /task(/flow提供SOP) → 执行 → /retro → /note → /review → (循环回明天的/briefing)
```

## 执行组

### /task — 防弹任务笔记

**一句话**：为任何要做的事创建一个结构化容器, 包含目标、材料、行动、"吐槽"四要素。

**触发词**：`"new task"` `"创建任务"` `"要做X"` `"start task"` `"任务"`

**什么时候用**：
- 开始任何新工作——大到项目里程碑，小到"回复那封邮件"
- 突然想到一件事要做
- 别人交代你一件事
- 自己想到一个想探索的方向

**什么时候不用**：
- 纯知识记录 → 用 `/note`
- 项目级规划 → 用 `/project`
- 做选择 → 用 `/decide`

**会产生什么**：
- `Tasks/active/{任务名}.md` — 带完整 frontmatter 和 4 要素的笔记
- 自动更新 index.md、log.md、相关 MOC
- 如果 vault 中有相关知识，自动填入"原始材料堆"

**任务状态流转**：
```
todo → doing → waiting → done → archived
  ↑                ↓
  └── 恢复阻塞 ────┘
```

**常见坑**：
- 只创建任务不填"问题与吐槽"——复盘时空空如也, 没材料可提取
- 太模糊的任务——"学 Rust"不是任务, "读完 Rust Book 第 3 章"才是
- 手动改任务 status 而不是用 `/task`——index.md 和 MOC 不会同步

**依赖**：无（这是入口技能）
**被依赖**：`/retro`、`/briefing`、`/project`

---

### /project — 多任务目标管理

**一句话**：把 agent-pmo 的 15 个企业级技能浓缩为 1 个个人用项目管理技能。

**触发词**：`"project"` `"goal"` `"目标"` `"项目"` `"新项目"`

**什么时候用**：
- 一件事需要多个任务协同完成
- 想跟踪一个目标的整体进度
- 想汇总多个相关任务的风险信号

**什么时候不用**：
- 单个独立任务 → 用 `/task`
- 每天例行事项 → 用 `/briefing`

**会产生什么**：
- `Projects/active/{项目名}.md` — 章程 + 里程碑 + 风险日志 + 进度脉搏
- 自动查询 vault 中历史类似项目的教训
- 任务通过 domain 匹配或手动关联自动链接到项目

**进度脉搏**：
- 🟢 on-track：任务按计划推进
- ⚠️ at-risk：有阻塞任务或里程碑可能逾期
- 🔴 stalled：14 天以上无关联任务活动

**常见坑**：
- 项目里只有 1 个任务——直接用 `/task` 就够了
- 项目创建了但从未更新进度脉搏——AI 每周会自动提醒
- 不想写完整章程——至少要写"成功的定义"这一句, 其他 AI 填充

**依赖**：`/task`（项目通过关联任务才有内容）
**被依赖**：`/retro`、`/briefing`、`/health`

---

### /briefing — 每日上下文简报

**一句话**：ThinkFlywheel 的核心融合点——任务层、知识层、记忆层在此交汇为一张可操作的早晨视图。

**触发词**：`"briefing"` `"早"` `"今天"` `"晨报"` `"早上好"`

**什么时候用**：
- 每天第一次打开 Claude Code 时
- 想快速了解当前全局状态时

**什么时候不用**：
- 不需要反复跑——一天一次足够

**会产生什么**：
- `Daily/YYYY-MM-DD.md` — 包含 6 个板块的简报
  1. 今日焦点（1-3 个最重要的事）
  2. 活跃任务（按优先级排列）
  3. 到期复习卡片（交叉引用活跃任务）
  4. 项目健康
  5. 历史预警（类似任务踩过的坑）
  6. 概览统计

**简报示例（使用一段时间后）**：
```
📋 活跃任务 5 个 | 🧠 到期复习 3 张 | ⚠️ 阻塞任务 1 个 | 🔴 即将到期 1 个

活跃任务:
| HIGH   | [[Q2 OKR 复盘报告]] | doing | 等财务数据 | ⚠️ 3天前 |
| MEDIUM | [[修复登录超时]]    | todo  | 开始排查   | 今天     |

到期复习（关联活跃任务）:
| [[SBI 反馈框架]]          | → [[Q2 OKR 复盘报告]] 💡 |
| [[数据可视化的3原则]]      | (无关联任务)             |

项目健康:
| [[Q2 OKR]] | 🟢 on-track | 3/5 活跃 |
```

**常见坑**：
- 初期 vault 里没内容, 简报很"瘦"——正常, 用两周就有料了
- 历史预警在 Phase 1-2 可能为空——需要积累足够历史任务数据
- Daily 文件保留 14 天, 旧的 AI 会提示清理

**依赖**：`/task`、`/project`、`/review`（简报消费它们的产出）
**被依赖**：无（简报是终点, 也是新起点——它指导今天的行动）

---

### /flow — 永久型任务笔记

**一句话**：把反复做的事情固化为标准流程，task 引用后自动继承步骤和检查清单。

**触发词**：`"flow"` `"流程"` `"SOP"` `"常做的事"` `"流程化"`

**什么时候用**：
- 同一件事反复做（周报、月度复盘、客户汇报）
- 有固定步骤的工作（如"项目立项审批"）
- 包含易错点的复杂操作需要检查清单

**什么时候不用**：
- 只做一次的任务 → 用 `/task`
- 个人偏好而非标准流程 → `/note` 存为卡片

**会产生什么**：
- `Flows/{domain}/{流程名}.md` — 适用场景 + 流程目标 + 标准步骤 + 易错点 + 迭代日志
- task 引用 flow 后自动继承步骤
- `/retro` 时经验回写到 flow 的"迭代日志"

**常见坑**：
- 把不重复的事情写成 flow——先做 3 次再固化
- flow 步骤太多太细——保持 5-8 步，用检查清单承载细节

**依赖**：`/task`（task 通过 flow 字段引用）
**被依赖**：`/retro`（经验回写）

---

### /meeting — 会议纪要

**一句话**：结构化记录会议内容、行动项、决议和风险，自动关联相关任务和项目。

**触发词**：`"meeting"` `"会议"` `"转录"` `"会议纪要"` `"开会"`

**什么时候用**：
- 开完任何需要跟进的会议
- 需要记录决议和行动项
- 会议中有多个议题需要拆解

**什么时候不用**：
- 3 分钟的随口交流——不需会议纪要
- 纯社交/闲聊——没有行动项产出

**会产生什么**：
- `Cards/reading/{会议主题} — YYYY-MM-DD.md` — 会议摘要 + 结构化行动/决议/风险追踪
- 自动提取行动项候选（提示创建 /task）
- 关联项目自动更新

**常见坑**：
- 会议结束太久才记录——当天完成
- 行动项只记录不跟踪——用 /task 为每个行动项建任务

**依赖**：`/task`（行动项转化）、`/project`（项目关联）
**被依赖**：`/briefing`（后续简报提醒未关闭行动项）

## 知识组

### /ingest — 原始材料处理

**一句话**：把文章、URL、PDF 处理成阅读摘要, 自动触发知识提取。

**触发词**：`"ingest"` `"process"` `"处理"` `"阅读"` `"读一下"` `"分析这篇"`

**什么时候用**：
- 读了一篇好文章想留下笔记
- 看到一篇论文想提取关键概念
- 网页文章想剪藏到 vault

**什么时候不用**：
- 三行字的 tweet——不值得走完整流程
- 已经在 Obsidian Web Clipper 里处理过的——直接丢到 Sources/inbox/ 再 /ingest

**处理深度**：
- **quick**（默认）：提取核心论点 + 关键论据 + "与我何干"
- **deep**：quick 基础上 + vault 交叉引用 + 矛盾检测 + 行动关联

**会产生什么**：
- `Cards/reading/{标题} — 阅读摘要.md`
- 自动触发 `/note` 双提议——从文章中提取原子卡片
- 源文件从 inbox 移到 processed

**流程**：
```
Sources/inbox/ → /ingest → Cards/reading/ (摘要)
                 ↓ (自动)
              /note 双提议 → Cards/atomics/ (知识点)
                 ↓
              /review → FSRS-6 复习
```

**常见坑**：
- 内容少于 500 字——跳过双提议, 不值得提取原子卡片
- 与已有卡片高度重复——不建新卡, 更新已有卡片
- deep 模式可能比较慢——日常用 quick, 重要文章用 deep

**依赖**：触发 `/note`、`/review`
**被依赖**：`/query`（读过的文章可被检索）

---

### /note — 知识提取（双提议）

**一句话**：vault 中知识类卡片的唯一写入通道。AI 提议 wikilinks + 原子卡片, 你确认后写入。

**触发词**：`"note"` `"做笔记"` `"记下来"` `"拆卡片"` `"存到 ob"`

**什么时候用**：
- 对话或思考中产生了值得保留的认知
- `/ingest` 处理完文章后（自动触发）
- `/retro` 复盘后提取了教训（自动触发）

**什么时候不用**：
- 创建任务 → 用 `/task`
- 阅读来源处理 → 用 `/ingest`（它内部会触发 /note）

**双提议机制**：
1. **提议 1: Wikilinks** — AI 扫描对话中提到的概念, 建议链接到 vault 中已有卡片
2. **提议 2: 原子卡片** — AI 建议新建的知识卡片, 每张一句话描述

你选择：全部接受 / 勾选部分 / 全部拒绝。

**会产生什么**：
- 研究摘要（一张叙事性卡片, 保留讨论脉络）
- 原子卡片（独立知识点, 进入 FSRS-6 复习）
- insight 卡片（教训和模式）
- 自动更新 index.md 和相关 MOC

**地图 + 石头模型**：
- **研究摘要 = 地图**：保留推理链条和结论, 读这张就能还原整个研究过程
- **原子卡片 = 石头**：独立的知识单元, 脱离上下文也能理解, 进入间隔重复

**常见坑**：
- 每次都全盘接受 AI 的提议——质量 > 数量, 宁少勿滥
- 卡片写得像笔记标题而非独立知识点——每张脱离上下文也必须能读懂
- 跳过了 wikilink 提议——链接是 wiki 的价值所在

**依赖**：`/ingest`、`/retro`、`/query` 都可触发它
**被依赖**：`/review`（原子卡片进入 FSRS）、`/briefing`（知识浮现于晨报）

---

### /query — Vault 搜索

**一句话**：不是 grep——而是综合多张卡片, 给出带 wikilink 引用的结构化回答。好的回答可以存回 wiki。

**触发词**：`"query"` `"find"` `"搜索"` `"找"` `"查"`

**什么时候用**：
- 想知道自己记录过的某个概念
- 想找历史任务中的某个决策或教训
- 想了解自己对某个领域的全部知识

**搜索策略（按优先级）**：
1. 精确匹配标题
2. 标签过滤（domain + 关键词）
3. 全文内容搜索
4. 关联扩展（沿着 wikilink 追 2 跳）

**查询类型示例**：

| 查询类型 | 示例 | 策略 |
|---------|------|------|
| 概念查询 | "什么是 SBI 反馈框架" | 标题匹配 → 内容搜索 |
| 关联查询 | "X 和 Y 有什么关系" | 两张卡片 + wikilink 路径追踪 |
| 历史查询 | "我上次处理类似问题怎么做的" | 搜索 archived tasks + decisions |
| 教训查询 | "这种类型任务有什么坑" | 搜索 insight + domain 匹配 |

**常见坑**：
- vault 初期内容少, 搜不到东西——正常, 积累 30+ 卡片后才有检索价值
- 好的回答记得保存——`/query` 综合出的新分析可以触发 `/note` 存为卡片

**依赖**：index.md、MOC（搜索的索引基础）
**被依赖**：`/note`（好答案存为新卡片）

## 记忆组

### /retro — 任务复盘 + 知识提取

**一句话**：ThinkFlywheel 的关键桥接技能——将行动转化为知识。其他系统都不具备的核心能力。

**触发词**：`"retro"` `"done"` `"完成"` `"复盘"` `"close"`

**什么时候用**：
- 任务完成后
- 任务中途放弃（复盘"放弃是对的决策还是逃避"）
- 项目阶段性复盘

**什么时候不用**：
- 任务还在进行中——继续执行, 完成了再来

**复盘流程**：
1. 读取任务的 4 要素（目标、材料、行动、吐槽）
2. AI 分析"问题与吐槽"中的模式：沟通问题、范围问题、知识缺口、流程问题、工具问题、认知偏差
3. 检测跨任务重复出现的模式（搜索同 domain 历史任务）
4. 自动触发 `/note` 双提议——从复盘材料中提取 insight + atomic 卡片
5. 归档任务：`status: archived`, 移到 `Tasks/archived/`
6. 如果是项目下的任务, 更新项目风险日志

**会产生什么**：
- `Reviews/retro/{任务名} — Retro.md` — 复盘笔记（目标 vs 实际、差距分析、关键教训）
- insight 卡片（教训和模式）→ 进入 FSRS
- atomic 卡片（知识点）→ 进入 FSRS

**即使没有问题也是宝贵信号**："为什么这次这么顺利？"可以提取可复制的成功模式。

**常见坑**：
- 任务没有填"问题与吐槽"就完成了——复盘价值不大, 但仍然做（"为什么这么顺利？"）
- 每次都跳过复盘——知识不提取, 飞轮断裂。让 `/health full` 帮你找未复盘的任务
- 接受太多 AI 提取的卡片——质量 > 数量, 挑最有价值的 1-2 张

**依赖**：`/task`（复盘需要任务笔记）、`/note`（知识提取）
**被依赖**：`/review`（卡片进入 FSRS）、`/briefing`（后续晨报中浮现）

---

### /review — 间隔重复

**一句话**：FSRS-6 间隔重复。把知识从 vault 推入你的大脑。

**触发词**：`"review"` `"复习"` `"今天复习什么"`

**什么时候用**：
- 每天一次（建议晚上, 5-10 分钟）
- Cards/atomics/ 里有卡片了就开始

**复习流程**：
1. 自动扫描新卡片并注册到 FSRS
2. 获取今日到期卡片
3. 逐张展示, 用户回忆后自评：
   - **1 / Again** — 完全忘了 → 短期重来
   - **2 / Hard** — 记得一点 → 稍长间隔
   - **3 / Good** — 基本记得 → 标准间隔
   - **4 / Easy** — 太简单 → 大幅延长间隔

**评级影响**：
- Again → stability 降至最低, difficulty 升高
- Hard → stability 小幅增长, 有惩罚系数
- Good → stability 正常增长
- Easy → stability 大幅增长, 有奖励系数

**常见坑**：
- 总评 Good（3）——如果你每次都选 Good, 算法无法区分难易。实事求是
- 跳过了几天——不要一次清完积压。每天 `--limit 5`, 慢慢追平
- 某张卡片连续 5 次 Again——卡片可能写得太模糊, 考虑改写

**依赖**：`/note`、`/retro`（卡片来源）
**被依赖**：`/briefing`（到期卡片出现于晨报）、`/health`（检查复习积压）

## 治理组

### /health — 系统健康检查

**一句话**：跨系统体检。不只是 wiki 是否断裂——检查知识-行动断层、任务僵死、领域平衡、SR 积压。

**触发词**：`"health"` `"check"` `"体检"` `"lint"` `"系统健康"`

**什么时候用**：
- quick：随时, 30 秒扫描
- full：每周一次（建议周日晚）

**quick 模式（6 项检查）**：
1. 链接健康 — broken wikilinks
2. 任务僵死 — 14+ 天未更新
3. 复习积压 — overdue 卡片数
4. 项目异常 — 进度脉搏与任务状态矛盾
5. 孤儿卡片 — 入站链接 = 0
6. 空 MOC 区间

**full 模式（额外 4 项）**：
7. 知识-行动断层 — mastered 卡片从未被任务引用
8. 领域平衡 — 7 个领域的卡片分布
9. 矛盾检测 — 结论相反的卡片对
10. 溯源链完整性 — source 缺失的卡片

**评分维度**：

| 维度 | 满分 | 扣分规则 |
|------|------|---------|
| 链接健康 | 20 | 每个断链 -5, 每张孤儿 -2 |
| 结构完整性 | 5 | 每个空 MOC section -1 |
| 任务活力 | 20 | 僵死 14 天 -5, 30 天 -10 |
| 知识-行动一致 | 20 | mastered未引用 -3, 未复盘 -5 |
| 记忆保持 | 15 | overdue < 10 OK, > 30 -10 |
| 领域平衡 | 10 | 每个 0% 领域 -5 |
| 溯源完整 | 10 | 每个无 source -2 |

**健康等级**：
- 90-100 🟢 优秀
- 70-89 🟡 良好
- 50-69 ⚠️ 需关注
- < 50 🔴 需修复

**重要原则**：`/health` 只诊断, 不自动修复。修复建议需你确认后执行。

### /decide — 结构化决策

**一句话**：不是帮你做决策——而是帮你追踪决策质量。慢慢学会自己的偏见和模式。

**触发词**：`"decide"` `"decision"` `"决策"` `"决定"` `"选择"`

**什么时候用**：
- 做重要选择（可能影响未来几周/月）
- 在两个或更多选项间纠结
- 想做决定但不确定是否遗漏了选项

**什么时候不用**：
- 日常小事（中午吃什么）——不值得
- 紧急到没时间走流程——事后补录最小版本

**决策流程**：
1. 查询 vault 中历史类似决策 + 相关知识 + 相关教训
2. AI 辅助构建选项（但不能替你做决策）
3. 创建 `Decisions/DEC-YYYY-NNN.md`
4. 注册复查提醒（30 天后, FSRS 调度）

**决策记录包含**：
- 上下文和约束
- 所有选项的利弊风险最坏情况
- 选择 + 理由 + 关键假设
- 预期结果 + 复查日期

**复查机制**：
- 30 天后 FSRS 提醒复查
- 对比实际结果和预期
- 决策被推翻 → 创建 insight 卡片捕获教训
- 这是最有价值的元认知训练

**常见坑**：
- 只记录重大决策——小事也有模式, 积累多了能发现自己的决策偏见
- 跳过复查——不复查就没学到任何东西, 决策记录等于白做

## 学习顺序

按这个顺序引入技能, 逐步增加复杂度：

| 阶段 | 技能 | 为什么要这个顺序 |
|------|------|-----------------|
| **Phase 1** | `/task` `/briefing` | 先建立"任务→每日视图"的基础循环。这是系统的骨架 |
| **Phase 2** | `/note` `/ingest` `/query` `/meeting` | 有了任务, 知识开始积累。阅读→摘要→卡片→可检索。会议是信息来源之一 |
| **Phase 3** | `/review` | 知识库有一定量了, 开始把知识推入长期记忆 |
| **Phase 4** | `/project` `/retro` `/decide` `/flow` | 系统"点亮"：多任务协调 + 复盘提取 + 决策追踪 + 流程固化 |
| **Phase 5** | `/health` | 系统足够复杂了, 需要治理层来维护健康 |

详细采用计划见 [上手指南 Phase-by-Phase](getting-started.md#5-phase-by-phase-采用指南)。
